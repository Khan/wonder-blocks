# Wonder Blocks — design-sync notes

Wonder Blocks is a **multi-package** monorepo (~38 `@khanacademy/wonder-blocks-*` packages), not a
single-package DS. Storybook shape. These notes capture what makes the sync work.

## Build prerequisites
- **`.d.ts` are NOT committed/prebuilt** — only JS `dist/` ships. Run `pnpm tsc --build tsconfig-build.json`
  (a.k.a. `pnpm build:types`) BEFORE the converter, or every component matches 0 exports.
- `pnpm build` (or the existing `dist/`) provides the JS bundles. Repo was clean/unchanged as of the first sync,
  so the committed `dist/` matched source; re-syncs should rebuild if source changed.
- Reference storybook: `npx storybook build -c .storybook -o .design-sync/sb-reference`.

## Multi-package bundling
- **[GENERAL] Barrel entry** `.design-sync/bundle-entry.mjs` re-exports each package's DEFAULT export under its
  component name — `export *` (the converter's extraEntries mechanism) drops default exports, and most WB main
  components (Banner, BirthdayPicker, Button, Clickable, IconButton, Link, Pill, SearchField, Switch, Toolbar,
  Tooltip) are default exports. The barrel is listed in `cfg.extraEntries` as `../../.design-sync/bundle-entry.mjs`
  (package-relative from `packages/wonder-blocks-core`, with an explicit `../` so it's treated as a path entry).
  `cfg.entry` is core's dist; `globalName` = `WonderBlocks`.
- Every visual `wonder-blocks-*` package is in `cfg.extraEntries` so story imports resolve to the global.
  Excluded: `testing`, `testing-core` (test-only, would poison the bundle), `eslint-plugin-wonder-blocks`.

## Forks (`.design-sync/overrides/`, declared in cfg.libOverrides)
- **[GENERAL] `source-storybook.mjs`** — only include stories tagged **`manifest`** (WB's own canonical-story
  marker via `experimentalComponentsManifest`). Drops Testing/Snapshots/Playtesting noise AND WB's `deprecated`
  components (Pill, Layout/MediaLayout/Spring/Strut, deprecated Typography variants) — this is correct/desired.
- **[GENERAL] `story-imports.mjs`** — two changes:
  1. Map each WB package's DEFAULT import (`import Button from '@khanacademy/wonder-blocks-button'`) to its
     component name on the global (`WB_PKG_DEFAULTS`). Without it, default-export components render
     "Element type is invalid" / empty (the bare-package shim returns the whole namespace object).
  2. **[GENERAL] base64 SVG loader** (`svgBase64` plugin) — load `.svg` as `data:image/svg+xml;base64,...`
     instead of esbuild's default `dataurl` (which emits raw `<`, spaces, `"`, `#`). PhosphorIcon injects the
     icon via **Aphrodite** as an UNQUOTED CSS `url(...)` mask; raw special chars break the rule and the browser
     drops the mask, rendering every icon as a solid square. Base64 is CSS-safe. This fixes icons across the
     whole DS (Button, IconButton, Badge, Cell, Breadcrumbs, dialogs' close button, …).

## Theme — Shape Your Learning / Thunderblocks (default)
- **[GENERAL] The DS defaults to the Shape Your Learning / Thunderblocks LIGHT theme**, per product requirement.
  Set via `cfg.provider = {component: "ThemeSwitcher", props: {theme: "thunderblocks"}}` — ThemeSwitcher renders
  `<div data-wb-theme="thunderblocks">`, and the shipped `tokens/index.css` provides the `[data-wb-theme='thunderblocks']`
  scoped vars. SYL brand color is indigo `#5753FA`. Theme values: `default` (Wonder Blocks), `thunderblocks`
  (SYL light), `syl-dark` (SYL dark, WIP).
- Setting `cfg.provider` replaces the storybook decorators as the preview wrapper (announcer/zoom/direction
  decorators are dropped — fine for static previews).
- The compare harness (`.ds-sync/storybook/compare.mjs`) is patched to load the storybook REFERENCE with
  `&globals=theme:thunderblocks` (env `DS_SB_GLOBALS`) so both sides match. **This staged file is regenerated by
  the `cp -r` step on re-sync — reapply the patch (or set DS_SB_GLOBALS) before re-grading changed components.**
- Applying the theme also fixes tokens that are only defined under a `[data-wb-theme]` scope (e.g. some checked-state
  backgrounds were missing before a theme was applied).

## Base reset / root font-size — post-build fix (CRITICAL, run every build)
- **[GENERAL]** WB typography + spacing tokens are **rem-based against a 10px root** (`html { font-size: 62.5% }`
  → 1rem = 10px). WB's Storybook applies this via `static/sb-styles/preview.css`, but the converter only scrapes
  component CSS, so the shipped `styles.css` closure was MISSING it → in claude.ai/design (html defaults to 16px)
  **all type rendered 1.6× too large** (16/10), and px-based radii looked too small next to the inflated text.
- Fix: **`node .design-sync/inject-base-css.mjs ds-bundle .design-sync/base-reset.css`** — copies
  `.design-sync/base-reset.css` → `ds-bundle/base.css` and prepends `@import "./base.css";` to `styles.css`
  (first, so the root font-size applies before tokens/components), then refreshes the anchor's `styleSha`.
  `base-reset.css` = `html{font-size:62.5%}` + `body{font-size:1.6rem}` + `[data-wb-theme]{color: var(--wb-semanticColor-core-foreground-neutral-strong)}` + dark `color-scheme`.
  **RUN IT AFTER EVERY build (with fix-bundle-svgs), before validate/upload.** Verified: html computes to 10px,
  Button ~13.3px / radius 8px, and typography previews now match the Storybook scale exactly.
- The conventions header tells the design agent the DS assumes a 10px root; the shipped `base.css` enforces it so
  designs don't need to.

## Baked-in icons — post-build fix (CRITICAL, run every build)
- **[GENERAL]** Two icon classes were broken as solid squares:
  1. Story-imported SVGs (PhosphorIcon custom-icon stories, Button startIcon) — fixed by the `svgBase64` plugin in
     the `story-imports.mjs` fork.
  2. **Icons baked into the component dist** (DueBadge clock, Checkbox checkmark, dropdown carets, alert icons) —
     esbuild's `dataurl` loader in `lib/bundle.mjs` (app-contract, NOT forkable) inlines them into `_ds_bundle.js`
     as raw `data:image/svg+xml,<svg …>`. Same Aphrodite-unquoted-`url()` breakage → solid squares.
- Fix: **`node .design-sync/fix-bundle-svgs.mjs ds-bundle/_ds_bundle.js`** base64-encodes those data URLs.
  **RUN IT AFTER EVERY `package-build.mjs` / driver build, before validate/compare/upload.** It changed 15 data
  URLs on the first sync. Subagents do NOT rebuild the bundle (they use preview-rebuild), so it only needs running
  when the orchestrator rebuilds the bundle.

## titleMap
- `BodyText(New)` → `BodyText`, `Heading(New)` → `Heading` (typography's current components are titled "… (New)";
  the deprecated same-named variants are dropped by the manifest filter).

## Grid overflow overrides
- Many components flagged wide/escape → `cardMode: column` (keep all stories full width) or `single`
  (portals/overlays: DatePicker, Combobox, MultiSelect, SingleSelect, Popover, Tooltip, Tabs, NavigationTabs).
  Presentation-only; grades carry.

## Preview-harness limitations (accepted `close`s — component renders correctly)
These recur DS-wide; the component itself is faithful, only a Storybook-env-provided extra is absent.
- **Storybook `globals.backgrounds` not applied**: stories that set a dark canvas via `globals` (Banner "Dark Background") render the banner correctly but on the default light canvas. Accepted `close`.
- **Storybook `globals.direction` (RTL) not applied**: the preview compose harness hardcodes `globals:{}`, so RTL stories (SingleSelect "Right to Left") render LTR. Portaled menus need a document-level `dir`, so no per-story wrapper fixes it. Accepted `close`.
- **Storybook static/public assets not served**: demo `<img src="avatar.png">` / `logo.svg` in stories (Icon "Compatible Elements", some "Custom Icon" stories) don't resolve in the preview server → broken-image placeholder. The DS component is unaffected. Accepted `close`.
- **Play-function opened/post-interaction states**: stories whose `play` fn opens a menu / toggles a switch show the post-interaction state on the oracle but the initial JSX in the preview (ActionMenu "Custom Action Items", Combobox "Controlled…", Switch "Controlled"). Benign `close` — do NOT fake state in the .tsx.
- **CustomOpener** (dropdown) is a real WB export — keep it (not a story-demo artifact).
- **Hardcoded relative CSS asset URLs** (`url(./modal-above.png)`, `url(./modal-below.png)`): decorative graphics referenced by string URL don't resolve in the preview build (ModalDialog "With Above And Below", OnePaneDialog). Bundler-imported SVGs (FlexibleDialog celebration assets) DO resolve. Accepted `close`.
- **Preview text renders ~1.6x larger** than the storybook canvas (preview root font-size vs a fixed-px component frame). Affects preview CARDS only — the design agent consumes `_ds_bundle.js` directly, not the cards — so it does not affect designs built with the DS. Judge the component, not the frame.
- **Launcher/drawer stories** (ModalLauncher, DrawerLauncher, DrawerDialog) render only the trigger statically (no opened/play state) — both sides identical (match), but the launched dialog body isn't visually verified.
- Owned previews created for env-provided context the harness drops: `Tabs.tsx` (RTL story → `dir="rtl"` wrapper), `CircularSpinner.tsx` (Light spinner → dark backdrop).

## Known render warns / gotchas (triaged)
- **Brand fonts are now SHIPPED self-contained** via `cfg.extraFonts: ["../../static/jakarta.css", "../../static/lato.css"]`
  → the build copies the woff2s into `fonts/` and `styles.css` `@import`s `fonts/fonts.css` (14 @font-face rules,
  Plus Jakarta Sans + Lato). No longer relies on a remote font host. Inconsolata (mono) + Source Serif Pro still
  load via Google Fonts `@import` in styles.css (Google Fonts is CSP-allowed in the design runtime).
  NOTE: the first sync had left the brand font falling back; extraFonts fixed it. Keep this config on re-sync.
- **storybook-static reference renders PhosphorIcon icons BLANK** (an asset-serving gap on the oracle side).
  The PREVIEW renders real icons correctly (base64 fix, verified in a real browser). For icon-bearing components
  the preview is authoritative — do not grade a preview "mismatch" merely because the storybook side shows no icon.
- Preview text/cards often render at a slightly larger scale than the storybook canvas (card framing) — judge the
  component, not the surrounding frame.
- Group names: single-level titles ("Packages / Banner") land in group `packages` (cosmetic; DS-pane only).

## Solo phase (calibration) — all match
Button, PhosphorIcon, BodyText, OnePaneDialog graded match. These validate: default-export resolution, icons,
typography/fonts, and portal/overlay dialogs respectively.

## Re-sync risks
- `.design-sync/bundle-entry.mjs` is hand-maintained: if WB adds a NEW default-export component package, add it to
  the barrel AND to `WB_PKG_DEFAULTS` in the story-imports fork, or it renders broken.
- The `manifest`-tag filter depends on WB keeping `experimentalComponentsManifest` on; if WB drops it, the fork
  filters everything out — re-check.
- `build:types` must run on every re-sync where source changed (dist has no committed .d.ts).
- Story caps: Button (15 stories, 6 captured), OnePaneDialog (11/6), PhosphorIcon (8/6) — tail stories are
  verified-by-upload, not individually graded. Raise `--max-stories` if tail variants matter.
