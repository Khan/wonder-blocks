# Dark Mode

Dark mode is delivered as a Wonder Blocks theme named **Shape Your Learning -
Dark** (`syl-dark`), which is the dark version of the **Shape Your Learning**
(`thunderblocks`) theme.

All Wonder Blocks semantic color tokens and components are supported in the
`syl-dark` theme. When features are implemented using the design system, the UI
should support dark mode by default, assuming tokens and components are used
correctly.

Continue reading to learn how to best support dark themes.

<Banner
  text="Toggle the theme on this page to see how the examples adapt to dark mode."
/>

<br/>

## How theming works

The active theme is written to the nearest themed element as a `data-wb-theme`
attribute (one of `"default"`, `"thunderblocks"`, `"syl-dark"`). Tokens from
`@khanacademy/wonder-blocks-tokens` are exposed as CSS variables scoped
to that attribute, so the _same_ token resolves to a different value depending
on the theme.

Note: Consuming applications should have the `data-wb-theme` attribute set on the
`body` element to ensure the theme is properly set on portaled components like
modals, drawers, tooltips, and popovers. The `WonderBlocksThemeProvider` in
`frontend` will handle setting this attribute based on things like feature flags,
user settings, etc. Teams typically do not need to configure this since the
infrastructure is in place already for the apps that support dark mode.

For custom components and styling, use the `semanticColor` tokens from
`@khanacademy/wonder-blocks-tokens`, which will adapt based on the theme.

**Avoid using hardcoded hex or rgb colors**. They are not guaranteed to work
across light and dark themes.

**Watch for contrast.** A token that looks fine in light mode can fail contrast
in dark mode. Choose the token whose _role_ matches the element, then verify it
in dark mode. Don't pick a token by how it happens to look in one theme.

**Prefer a Wonder Blocks component over hand-colored UI.** If WB already ships a
component for what you're implementing, use it instead of styling your own. It
will support dark mode automatically.


If there is no `semanticColor` token that suits your use case, please reach out
to the Wonder Blocks team!

When adding graphics, consider how it will look across themes. There are some cases
where graphics will also need to adapt based on the theme. Use the
`semanticColor.graphics.*` tokens where possible.

#### Background Images

For background images with text on top, there's a chance that the text won't be
legible in dark mode, because the base font color will become inverted and the
background image will stay the same. This applies to things like Cards,
Modals, etc.

To account for this, use semantic color tokens for background colors where
possible. Some examples:

##### Background patterns

Instead of using an image with the CSS `background-image` property, breakdown
the image into parts so semantic color tokens can be applied to each part of the
image. This way, the background pattern colors will adapt in dark mode.

<Canvas of={DarkModeExamples.BackgroundPattern} layout="fullscreen" />

Here is an example of how to implement a background pattern:

**Step 1 - Background color:**
- Use a semantic color for the base background color

**Step 2 - Background pattern image:**
- Remove the background color from the background image
  - If the background image is an svg, remove the `<rect>` element with the
  hardcoded background color.
- After the background color has been removed, you should be left with the pattern.

**Step 3 - Mask image and placement:**
- Create a div with `mask-image` set to the pattern image
- Set the `background-color` to a semantic color token. This will be the color
applied to the pattern
- Set other mask image properties like `mask-position`, `mask-repeat`, `mask-size`
- Position the div on top of element with the base background color. Set
`z-index` to `-1`
- Set `aria-hidden` on the pattern since it is decorative

<Canvas of={DarkModeExamples.BackgroundPatternBreakdown} layout="fullscreen" />

##### Background with shapes

Another alternative to using the CSS `background-image` property is to use a
semantic color token for the background, and then place graphics on top of it.

<Canvas of={DarkModeExamples.BackgroundWithShapes} layout="fullscreen" />

Here is an example of how to implement a background with shapes:

**Step 1 - Background color:**
- Use a semantic color for the base background color

**Step 2 - Shapes:**
- Extract assets for each shape, so they can be positioned and styled separately
- These shapes can be inline svgs or masked images that use semantic color tokens
- If the shape colors work well in both light and dark themes, it is not necessary
to use semantic color tokens

**Step 3 - Placement:**
- Place the shapes on the element with the background color. Set `z-index` to `-1`
- Mark the shapes as decorative (set `aria-hidden`)

#### Icons

##### Single-colored icons

For single colored icons, use semantic color tokens with the
<a href="./?path=/docs/packages-icon-phosphoricon--docs">PhosphorIcon</a> component.
The `PhosphorIcon` component can be used with icons from `@phosphor-icons` or
custom svg icons (like logos), assuming they are to be filled with one color.

<Canvas of={DarkModeExamples.SingleColoredIcons} layout="fullscreen" />

##### Multi-colored icons

Use <a href="./?path=/docs/packages-icon-custom-icon-components--docs">custom icon components</a>
from Wonder Blocks, which are implemented to work across all themes:

<Canvas of={CustomIconStories.AllCustomIcons} layout="fullscreen" />

If the icon you need is not in Wonder Blocks, check if it exists in your project
or other shared libraries as an inline svg.

If one does not exist yet, create a React component returning the `<svg>`
element so that the svg is rendered inline. Replace any hardcoded colors for
properties like (`fill`, `stroke`, etc) and use semantic color graphics tokens.

Use the custom icon component with the
<a href="./?path=/docs/packages-icon-icon--docs">WB Icon</a> component
to provide sizing. Make sure the svg markup doesn't have hardcoded width or height
properties.

<Canvas of={DarkModeExamples.MultiColoredIcons} layout="fullscreen" />

#### Illustrations

There are some graphics that do not need to change colors based on the theme
(for example, Khanmigo accessories). For these cases, graphics should still use
colors from the design system.

Stay tuned for graphic palette token updates!

### Third-party libraries

Use semantic color tokens for third-party libraries that may assume a light theme.
Examples include: charting libraries, specialized UI components, etc.

## Testing

- Use the **Theme** toolbar in Storybook to switch the theme for a story
- **Always review features using light and dark themes.** A change that looks
  right in light mode can be unreadable in dark mode
