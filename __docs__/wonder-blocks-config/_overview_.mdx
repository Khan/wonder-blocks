# Config

`@khanacademy/wonder-blocks-config` configures the Wonder Blocks components in
your app. Currently, this covers i18n: the translated strings that Wonder Blocks
components render, and the locale they are translated into.

```sh
pnpm add @khanacademy/wonder-blocks-config
```

## Set up

Render a `WonderBlocksConfigProvider` near the root of your app and pass it the
translated strings and their locale through the `i18n` prop:

```tsx
import {WonderBlocksConfigProvider} from "@khanacademy/wonder-blocks-config";
import type {WonderBlocksStrings} from "@khanacademy/wonder-blocks-config";

const strings: WonderBlocksStrings = {
    iconAltOpensNewTab: "(se abre en una pestaña nueva)",
};

<WonderBlocksConfigProvider i18n={{strings, locale: "es"}}>
    <App />
</WonderBlocksConfigProvider>;
```

Without a provider, Wonder Blocks components use the default English strings
and the `en` locale.

See [`WonderBlocksConfigProvider`](?path=/docs/packages-config-wonderblocksconfigprovider--docs)
for more examples.

## Translating strings

The untranslated strings that Wonder Blocks components render are exported from
the `@khanacademy/wonder-blocks-config/strings` entry point, so they can be
passed to your translation pipeline. Each entry is keyed by the same name used
in `WonderBlocksStrings` and has a `message` to translate, plus a `context`
describing how the string is used to help translators:

```ts
import {strings} from "@khanacademy/wonder-blocks-config/strings";

// {
//     iconAltOpensNewTab: {
//         context: "Accessible name for an icon marking a link that opens in a new tab.",
//         message: "(opens in a new tab)",
//     },
// }
```

The translated output should match the `WonderBlocksStrings` type — an object
mapping each key to its translated string — which is what the `strings` field
of the `i18n` prop expects.

The default English strings are also exported as `defaultStringsEn` from the
same entry point.
